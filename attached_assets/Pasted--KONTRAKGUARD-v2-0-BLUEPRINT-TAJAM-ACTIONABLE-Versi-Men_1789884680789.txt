## BAGIAN 1: DEEP DIVE TEKNIS — AI/NLP ENGINE

Ini adalah **jantung intelektual** aplikasi. Tanpa AI yang akurat, aplikasi ini hanya menjadi "Google Drive yang mahal". Berikut detail teknisnya:

### 1.1 Arsitektur AI Pipeline

```
┌─────────────────────────────────────────────────────────────────┐
│                    AI CONTRACT ANALYSIS PIPELINE                │
└─────────────────────────────────────────────────────────────────┘

INPUT: PDF/DOCX Kontrak Konstruksi (Bahasa Indonesia/Inggris)
  │
  ▼
[STAGE 1: DOCUMENT INGESTION]
  ├── PDF Parser (PyMuPDF + pdfplumber)
  ├── Table Extractor (Camelot) — untuk BQ, jadwal, dll
  ├── OCR Engine (Tesseract + PaddleOCR) — untuk scan
  └── Layout Analyzer (LayoutLMv3) — pahami struktur dokumen
  │
  ▼
[STAGE 2: STRUCTURAL PARSING]
  ├── Pasal Detection (Regex + ML hybrid)
  │   └── Output: "Pasal 12.3", "Pasal 25.1.a", dll
  ├── Cross-Reference Resolver
  │   └── "Pasal 12.3 merujuk ke Pasal 25.1" → link otomatis
  ├── Annex/Lampiran Classifier
  │   └── Identifikasi: BQ, Spesifikasi, Jadwal, Gambar
  └── Entity Extractor (NER)
      └── Nama pihak, nilai kontrak, tanggal, lokasi
  │
  ▼
[STAGE 3: CLAUSE CLASSIFICATION & EXTRACTION]
  ├── Model: Fine-tuned LLM (berbasis Llama-3 8B atau Qwen2.5)
  │   └── Dilatih pada 10.000+ kontrak konstruksi Indonesia
  ├── Klasifikasi 23 Kategori Klausul:
  │   1. Lingkup Pekerjaan
  │   2. Nilai & Mekanisme Pembayaran
  │   3. Jangka Waktu
  │   4. Denda Keterlambatan
  │   5. Perpanjangan Waktu (EOT)
  │   6. Variation Order
  │   7. Force Majeure
  │   8. Pemutusan Kontrak (Terminasi)
  │   9. Penyelesaian Sengketa
  │   10. Asuransi
  │   11. Jaminan (Pelaksanaan, Uang Muka, Retensi)
  │   12. Retensi & DLP
  │   13. Subkontrak
  │   14. K3L (Keselamatan Kerja)
  │   15. Hak Kekayaan Intelektual
  │   16. Kerahasiaan
  │   17. Perubahan Hukum
  │   18. Pajak
  │   19. Audit
  │   20. Laporan & Dokumentasi
  │   21. Serah Terima (PHO/FHO)
  │   22. Cacat Mutu
  │   23. Klausul Tambahan (Special Conditions)
  │
  └── Output: Structured JSON per klausul
      {
        "clause_id": "12.3",
        "category": "denda_keterlambatan",
        "text": "Denda sebesar 2‰ per hari...",
        "entities": {
          "rate": "0.002",
          "base": "nilai_kontrak",
          "cap": null  ← RED FLAG: tidak ada batas maksimal
        },
        "risk_score": 0.85,
        "deviation_from_standard": "+0.0015 vs standar PUPR"
      }
  │
  ▼
[STAGE 4: RISK SCORING & BENCHMARKING]
  ├── Rule Engine (deterministic):
  │   └── "Jika denda > 1‰ → risk_score += 0.3"
  ├── ML Model (learned):
  │   └── Gradient Boosting trained pada 500+ kasus sengketa
  │       untuk memprediksi probabilitas sengketa per klausul
  └── Benchmark Database:
      └── Perbandingan dengan 50.000+ kontrak dalam database
  │
  ▼
[STAGE 5: OUTPUT GENERATION]
  ├── Risk Dashboard (visual)
  ├── Redline Report (perbandingan dengan template standar)
  ├── Obligation Extract (daftar kewajiban terstruktur)
  ├── Deadline Extract (semua tenggat waktu)
  └── Natural Language Summary (ringkasan eksekutif)
```

### 1.2 Strategi Training Data (Ini Kunci!)

**Masalah:** Tidak ada dataset publik kontrak konstruksi Indonesia yang besar.

**Solusi — Data Flywheel:**

```
FASE 1: SEED DATA (Bulan 1-6)
├── Kumpulkan 500 kontrak dari:
│   ├── Template PUPR (publik)
│   ├── Template FIDIC (terjemahan resmi)
│   ├── Kontrak sampel dari partner awal (dengan NDA)
│   ├── Putusan BANI yang dipublikasikan (untuk label "sengketa")
│
├── Annotasi manual oleh 5 lawyer konstruksi + 3 QS
│   └── Label: kategori klausul, risk level, entities
│
└── Output: Dataset terannotasi ~5.000 klausul

FASE 2: FINE-TUNING (Bulan 6-9)
├── Fine-tune LLM (Qwen2.5-14B atau Llama-3-8B)
│   ├── Task 1: Clause Classification (accuracy target: 92%)
│   ├── Task 2: Entity Extraction (F1 target: 88%)
│   ├── Task 3: Risk Scoring (Spearman correlation: 0.75+)
│   └── Task 4: Deviation Detection (precision target: 90%)
│
├── Teknik: LoRA (Low-Rank Adaptation) untuk efisiensi
└── Validasi: 5-fold cross-validation + expert review

FASE 3: PRODUCTION & FEEDBACK LOOP (Bulan 9+)
├── Deploy model di production
├── Setiap analisis AI → user review → feedback
│   └── "Apakah analisis ini akurat?" [Ya/Tidak/Edit]
├── Feedback masuk ke retraining pipeline
│   └── Model di-retrain setiap bulan
└── Dalam 12 bulan: dataset tumbuh 10x, akurasi naik signifikan
```

### 1.3 Benchmark Akurasi yang Harus Dicapai

| Task | Target Akurasi | Cara Ukur |
|---|---|---|
| Deteksi struktur pasal | 98% | Exact match dengan struktur asli |
| Klasifikasi kategori klausul | 92% | F1-score vs label expert |
| Ekstraksi entitas (nilai, tanggal) | 95% | Exact match |
| Deteksi deviasi dari standar | 90% | Precision-recall vs expert |
| Risk scoring (rank ordering) | 0.75 Spearman | Korelasi dengan penilaian lawyer |
| Ringkasan eksekutif | 4.0/5.0 | Rating user (lawyer konstruksi) |

**Jika akurasi di bawah target → jangan rilis fitur.** Lebih baik fitur manual + AI-assisted daripada AI yang salah dan menyesatkan.

### 2.2 Database Schema untuk Evidence Vault

```sql
-- Core immutable table
CREATE TABLE evidence_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID REFERENCES projects(id),
    item_type VARCHAR(50) NOT NULL,  -- 'photo', 'document', 'email', 'notice'
    
    -- Content
    content_hash SHA256 NOT NULL,     -- Hash konten (SHA-256)
    content_size BIGINT NOT NULL,
    storage_path VARCHAR(500) NOT NULL,
    
    -- Metadata (terpisah untuk query cepat)
    metadata JSONB NOT NULL,          -- GPS, EXIF, page count, dll
    
    -- Provenance
    uploaded_by UUID REFERENCES users(id),
    uploaded_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    device_fingerprint VARCHAR(200),
    ip_address INET,
    geolocation GEOGRAPHY(POINT),
    
    -- Chain
    previous_version_id UUID REFERENCES evidence_items(id),
    version INTEGER NOT NULL DEFAULT 1,
    is_latest BOOLEAN NOT NULL DEFAULT true,
    
    -- Blockchain anchor
    blockchain_tx_hash VARCHAR(100),  -- Hash transaksi di Ethereum/Polygon
    anchored_at TIMESTAMPTZ,
    
    -- Legal
    legal_hold BOOLEAN NOT NULL DEFAULT false,
    retention_until DATE,
    
    -- Immutable audit
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Hash chain verification
CREATE TABLE hash_chain (
    sequence BIGINT PRIMARY KEY,
    block_hash SHA256 NOT NULL,
    previous_hash SHA256,
    evidence_item_ids UUID[] NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    blockchain_tx_hash VARCHAR(100)
);

-- Audit log (also immutable)
CREATE TABLE audit_log (
    id BIGSERIAL PRIMARY KEY,
    timestamp TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    user_id UUID,
    action VARCHAR(50) NOT NULL,  -- 'VIEW', 'UPLOAD', 'DOWNLOAD', 'SIGN', etc
    resource_type VARCHAR(50),
    resource_id UUID,
    details JSONB,
    ip_address INET,
    user_agent TEXT,
    -- Hash of previous row for chain integrity
    row_hash SHA256 NOT NULL,
    previous_row_hash SHA256
);

-- Prevent any modification/deletion
REVOKE UPDATE, DELETE ON evidence_items FROM PUBLIC;
REVOKE UPDATE, DELETE ON audit_log FROM PUBLIC;

-- Only allow INSERT
CREATE POLICY immutable_evidence ON evidence_items
    FOR ALL USING (false)  -- No row-level updates/deletes
    WITH CHECK (true);     -- Only inserts allowed
```

| **Perubahan regulasi** drastis | Rendah | Sedang | Tim legal dedicated, update fitur dalam 30 hari, fleksibel arsitektur |
| **Data breach** | Rendah | Fatal | Enkripsi end-to-end, SOC 2 Type II, penetration test quarterly, cyber insurance |
| **Cash flow** — sales cycle panjang (enterprise 6-12 bulan) | Tinggi | Tinggi | Fokus awal ke SME (sales cycle 1-2 bulan), upfront annual payment discount, factoring invoice |
